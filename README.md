# opencode-tools

Личные инструменты для OpenCode: честный учёт работы агента — сколько было
заходов, шагов, времени и токенов — остаток на балансе провайдера и лимиты
OpenCode Go.

Время и стоимость берутся из локальной базы OpenCode
(`~/.local/share/opencode/opencode.db`). Наружу ходят только `balance`,
`limits`, строки футера и уведомления на телефон: это запросы к API
провайдера и к выбранному сервису пушей.

## Установка

Нужен Python 3.9+.

```sh
./install.sh
```

Скрипт прогоняет тесты и делает ссылку `~/.local/bin/opencode-tools`.
Заодно подключает TUI-плагин в `~/.config/opencode/cli.json` и серверный
плагин уведомлений в `~/.config/opencode/opencode.json`: после `/reload`
(или перезапуска TUI) в футере появляются строки `Работа: …`, `Go: …`
(только для провайдера `opencode-go`) и `Токены: …`. Удалить всё:
`./install.sh --uninstall`.

## Постоянная строка в TUI

В футере промпта:

```text
Работа: 1ч 12м · ход: 3м · потрачено $0.4200
Go: осталось 5ч 77% (4ч 44м) · нед 91% (3д) · мес 96% (29д)
Токены: 46,5M · вход 229,5k · из кэша 46,1M · выход 127,9k · 8,2 ток/с
```

`Работа` — суммарное время агента по текущей сессии и её субагентам,
`ход` — текущий ход, пока агент работает, `потрачено` — стоимость сессии
и её субагентов. У DeepSeek в первой строке вместо `Go:` появляется
`баланс DeepSeek: $10.14` — остаток у провайдера.

`Go` — остаток лимитов OpenCode Go: пятичасовое, недельное и месячное окна.
Проценты — сколько осталось, в скобках — время до сброса. Строка появляется,
только когда в промпте выбран провайдер `opencode-go`.

Строка `Токены` — токены сессии и её субагентов: `вход` (без кэша),
`из кэша`, `выход` (включая рассуждения) и темп сессии в выходных токенах
за секунду работы. Паузы между ходами не входят, параллельные субагенты считаются один
раз; это темп сессии, а не скорость генерации модели.

Время обновляется раз в секунду, баланс и лимиты Go — при запуске, раз в
5 минут и через пару секунд после завершения хода. Если баланс получить не
удалось, последняя часть просто не показывается. Токены считаются локально
и в сеть не ходят.

Плагин TUI лежит в `plugin/`, в `cli.json` добавляется путь к этой папке.
Серверный плагин уведомлений лежит в `notify/` и подключается в
`opencode.json`.

Если строки нет — выполните `/reload` или перезапустите OpenCode.


## Уведомления на телефон

Серверный плагин `notify/` присылает пуш в ntfy (и/или Telegram), когда
агенту нужен человек:

- `🔐 Needs permission: shell` — запрос разрешения, сразу (или через
  `INPUT_NOTIFY_SECONDS`);
- `❓ OpenCode asks you a question` — вопрос агента (`question`), так же;
- `💬 Waiting for your reply` — через 30 секунд после конца хода, один раз
  на ход; новый ход или отправленный промпт отменяют пуш;
- `💬 Waiting for your reply (a background task is still running)` — если
  фоновая команда или субагент всё ещё работают через
  `BACKGROUND_WAIT_LIMIT_SECONDS`;
- `⚠️ OpenCode stopped with an error` — ход завершился ошибкой.

Заголовок: `OpenCode · <репозиторий> · <название сессии> [<короткий ID>]`.
Для worktree — `<репозиторий> (<worktree>)`. Тексты промптов, команды, пути
и содержимое файлов не отправляются: в теле только тип события (и действие
разрешения), имя проекта и название сессии.

Настройки — общий с Claude Code и codex-tools файл `notify.env`. Порядок:
`OPENCODE_NOTIFY_CONFIG` → `~/.config/opencode/notify.env` →
`$CODEX_HOME/notify.env` (обычно `~/.codex/notify.env`) →
`~/.claude/notify.env`. Если есть конфиг Codex или Claude, отдельный топик
не нужен: плагин берёт его. Если ни одного файла нет, `install.sh` создаёт
`~/.config/opencode/notify.env` с правами 0600 и случайным топиком.

```sh
NTFY_TOPIC=...
# NTFY_SERVER=https://ntfy.sh
# IDLE_NOTIFY_SECONDS=30
# INPUT_NOTIFY_SECONDS=0
# BACKGROUND_WAIT_LIMIT_SECONDS=900
# TELEGRAM_BOT_TOKEN=...
# TELEGRAM_CHAT_ID=...
```

`NTFY_TOPIC` — топик в приложении ntfy. Кто знает имя топика, тот может
читать его, поэтому топик — секрет. `INPUT_NOTIFY_SECONDS=0` — разрешения и
вопросы приходят сразу; поставьте 30, чтобы не дёргать, если вы у
компьютера. `BACKGROUND_WAIT_LIMIT_SECONDS` ограничивает ожидание фоновой
задачи. Telegram можно использовать вместе с ntfy или вместо него.

Плагин живёт в серверной части OpenCode, поэтому TUI для отправки не нужен.
Он подписан на `permission.asked`, `form.created` и `session.execution.*`.
Серверный поток событий в OpenCode 2.1.4 не присылает `session.idle`,
поэтому конец хода определяется по `session.execution.succeeded`.

Проверить после установки: создайте новый ход и не отвечайте 30 секунд —
должен прийти `💬 Waiting for your reply`. Топик и каналы перечитываются
перед каждой отправкой, а паузы (`IDLE_NOTIFY_SECONDS`,
`INPUT_NOTIFY_SECONDS`, `BACKGROUND_WAIT_LIMIT_SECONDS`) — при загрузке
плагина: после их правки выполните `/reload` или перезапустите OpenCode.


## Баланс провайдера

```text
$ opencode-tools balance

OpenCode · баланс

  DeepSeek              $10.15
    оплачено            $10.15
    бонусы               $0.00
```

Ключ берётся из `~/.local/share/opencode/auth.json`, остаток запрашивается
у провайдера. Сейчас поддержан только DeepSeek (`GET /user/balance`).
У OpenCode Zen публичного API баланса нет, поэтому его остаток не показать.
Это же значение выводится в футере TUI.

`--provider deepseek` — выбрать провайдера явно, `--json` — машинный вывод.
Ключ нигде не печатается.


## Токены и темп

`opencode-tools time` показывает тот же разбор, что и строка `Токены` футера:

```text
  стоимость       $0.1081
  токенов         12,3M
    вход          116,7k
    из кэша       12,1M
    выход         90,4k
      рассуждения 58,8k
  темп            121,0 ток/с
```

Сумма — все токены шагов семейства сессий: вход + чтение/запись кэша +
выход + рассуждения. `вход` — только некэшированная часть, `выход` включает
рассуждения. В `--json` это объект `tokens` с полями `input`, `cache_read`,
`cache_write`, `output`, `reasoning`, `total`, `generated`.


## Лимиты OpenCode Go

```text
$ opencode-tools limits

OpenCode · лимиты Go

  окно          осталось             сброс
────────────────────────────────────────
  5 часов            77%       20.11 03:22
  неделя             91%       23.11 03:00
  месяц              96%       19.12 22:05
```

Go отдаёт долю использованного лимита, а инструмент показывает остаток
внутри каждого окна. Пятичасовое окно вмещает 20% месячного лимита,
недельное — 50%, поэтому 100% в пятичасовом окне — это не весь месяц.
Месячное окно сбрасывается с новым оплаченным периодом. В долларах остаток
зависит от выбранной модели: у каждой модели свой месячный лимит. Ключ
берётся из хранилища credential OpenCode (`auth.json` или таблица
`credential` в `opencode.db`), ключ нигде не печатается. `--json` —
машинный вывод, `--timeout` — таймаут запроса.

Строка `Go:` в футере запрашивается только при выбранном провайдере
`opencode-go`; на других провайдерах она не появляется и сеть не трогается.


## Что показывает

```text
$ opencode-tools stats --days 7

OpenCode · 11–17 ноября 2026

  заходов               5
  промптов             21
  шагов агента        308
  время работы     31м 27с
  инструментов        429
    правок файлов      56
  стоимость        $0.3131

день         заходы  промпты   шаги    время   инстр.        $
──────────────────────────────────────────────────────────────
12.11             1        2     29       3м       59    0.037
13.11             1       11     86       8м      103    0.105
17.11             3        8    193      19м      267    0.172
──────────────────────────────────────────────────────────────
итого             5       21    308      31м      429    0.313
```

* **заход** — сессия OpenCode (корневая; субагенты считаются отдельной строкой);
* **промпт** — сообщение пользователя;
* **шаг** — один ответ агента (assistant step, включая вызовы инструментов);
* **время работы** — сумма длительностей шагов, без пауз между ходами;
* **инструменты** — вызовы инструментов, **правки файлов** — `edit`/`write`/`patch`;
* **стоимость** — из сообщений агента.

## Команды

```sh
opencode-tools time                    # работа и токены последней сессии
opencode-tools time --session ses_...  # конкретная сессия (можно начало id)
opencode-tools time --json

opencode-tools stats                   # сегодня
opencode-tools stats --days 7          # последние 7 дней
opencode-tools stats --days 30 --sessions
opencode-tools stats --all             # всё время, по месяцам
opencode-tools stats --project .       # только текущий проект
opencode-tools stats --json

opencode-tools balance                 # баланс провайдера (DeepSeek)
opencode-tools balance --json

opencode-tools limits                  # остаток лимитов OpenCode Go
opencode-tools limits --json

opencode-tools watch                   # живая строка, обновляется раз в секунду
```

`watch` удобно держать в отдельной панели терминала:

```text
Работа: 1ч 12м · ход: 3м 40с
```

В TUI OpenCode любую команду можно выполнить через `!`:

```text
!opencode-tools stats --days 7
```

## Как считается время

Единица работы — шаг агента: `time.created → time.completed` в
`session_message`. Шаги внутри хода идут подряд, поэтому объединение их
интервалов и есть время, когда агент был занят.

* паузы между ходами (пока пользователь читает или думает) не входят;
* параллельные субагенты объединяются, а не суммируются дважды;
* незавершённый шаг моложе 15 минут считается текущим и растёт до «сейчас»;
* шаги длиннее 30 минут отбрасываются как артефакт миграции;
* для сессий, перенесённых из старого хранилища V1, время берётся из таблицы
  `message`: в V2 у них `completed` записан моментом миграции;
* интервалы, переходящие через полночь, делятся между сутками.

Это время работы агента, а не время CPU и не время, проведённое за компьютером.
Стоимость и токены — из тех же сообщений, поэтому могут немного расходиться с
`opencode stats` (там сессионные счётчики).

## Ограничения

* Работает с OpenCode V2 (`session_v2` / `session_message`). Для V1-базы
  скажет, каких таблиц не хватает.
* Показывает только локальные сессии этого компьютера.
* Баланс умеет получать только у DeepSeek: у OpenCode Zen публичного API нет.
* Лимиты умеет получать только у OpenCode Go; у обычного OpenCode Zen их нет.
* Часовой пояс — локальный.
